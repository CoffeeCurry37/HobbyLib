## 2. B阶段具体实现

### 隔离环境与最小数据改动

沿用tools/pilot-workbench和本地work/pilot-300，不开正式D1写入、生产维护或Site部署。原manifest、baseline-30、proposals-30和官方证据原件保留；新增版本化实验结果与本地数据库副本，例如work/pilot-300-v2。端口选可用的本机地址，启动时明确显示环境与数据路径。

优先为实验增加以下结构，不先重写正式Item系统：

- 商品展示档案：一级作品/系列/弹次，二级edition/member/bonus，以及临时sale-lot；展示分组不等于身份归并。
- 版本与发行事实：work、edition、platform、medium、SKU、活动、购买条件、独立售卖/集换/固定套装属性及证据。
- 出售范围：包含成员、数量、已知缺件、未知项；临时条目有效状态由挂牌决定，不让价格进入永久身份。
- 字段级人工反馈：来源为本次聊天，绑定输入/建议哈希与适用范围；单独导入/展示，不伪装成用户在旧界面逐条点击确认。
- 简介及标签：规范事实生成1–3句，完整收录角色独立保存；人工改写受保护。事实未变时不重写文字。
- 目录与证据完整度：已确认成员、候选成员、官方总数、未知槽位分开；每个候选生成不建档/临时/永久/人工复查的理由。

P001–P004先展示本轮已保存的简介示例。Fes类按活动+类型+代表角色写简短简介。漫画剧情只有出版社该卷简介支持才写，不从系列常识推断；无证据时类型/卷次/作者已足够，不强凑第三句。

## 4. 人工审核、准确率与上线边界

用户下一次重点看上述六组演示及全部高风险项，不必重新核查每个已接受角色。AI先整理证据和可选决定；用户裁决目录含义、来源冲突与新收录边界。单商品意见只应用于该商品；一般规则标注作用范围，不能自动推广全库。

评测至少分开报告：

- 自动匹配精确率 = 自动匹配中正确数/自动匹配数；身份严重误配单列。
- 自动覆盖率 = 自动给出可执行决定数/全部样本数；临时收录、拒收与人工暂缓分列，不能把全部拒绝当高性能。
- 候选召回目标≥98%（仅在已确认可匹配正例中计算）；错误新品/重复建档率、无依据字段率、完整目录成员准确性。
- 按来源/品类报告分母、错误、未知、有效组数和置信区间；同系列多挂牌不当完全独立样本。
- 证据可追溯100%；已知卷号/作品/版本/本体特典冲突的自动误配0；个人数据丢失0。
- 普通人工案件审核中位数目标≤2分钟；困难案件单列；同时报告转人工比例与积压。

99.5%自动匹配准确率仍是后续目标，200或300条试点无法可靠证明。扩大自动上线前继续积累独立新挂牌，具体样本量和区间按实际自动决定数及相关性计算。首30用户认可不能记作盲测30/30；本次人工反馈也不自动改变原五项checks的verified状态。

原32条生产修订及五边已完成，禁止重放001–006。#484重复与#495未知/缺少展示仍单列待办；如下一阶段借其做回归，只读/复制检查，不能借试点顺手改生产。

## 5. 成本、工具与调整策略

继续由当前具备仓库/网页工具的Codex完成隔离实现和验证，用户做领域裁决。会话可辅助少量调查；未来自动扫描需要后台任务、来源适配和模型接口。此方案不要求更换模型，也不将人工辅助研究计入无人值守能力。

本轮新增付费API调用0；订阅/会话和人工成本未计量，不能称总成本为0。旧文档中的美元预算是历史情景值，不是本轮实测或已获付费授权。未来费用用实际记录计算：

总成本 = 模型输入/输出token × 执行时单价 + 搜索/OCR/图片/外部来源费用 + 托管 + 人工时间。分别报每条观察、每研究组、每个正确决定和每个审核案件的成本。定价在真正启用服务时核对，不在这里承诺固定金额完成。

建议先在30条V2测量后给70条与200条分别估算区间。未接付费API时继续会话辅助并标注；启用服务前才确定预算上限。以下为待调配置而非外部消费授权：

| 路径 | 初始控制建议 | 超限处理 |
| --- | --- | --- |
| 已知身份/目录 | 先查本地索引和缓存；事实未变不搜索 | 只刷新需要的挂牌状态 |
| 新系列/永久目录 | 每研究组先4次搜索、最多8页有效资料，再按收益决定 | 记录缺项，转人工或追加明确研究任务 |
| 图像消歧 | 文字/卡背优先，最多2轮候选图对照 | 不够清晰就未知，不凭模型自信确认 |
| 兑换码/大包 | 最多1次定向搜索或2页既有证据复核 | 保留IP/类型与未知，临时或暂缓 |
| 来源失败 | 一次尝试＋一个合规替代入口，再退避缓存 | 不循环刷新，不把失败作商品不存在 |

如果达不到理想效果，按错误原因调整：候选漏召回→编号/别名索引；证据有而误读→品类校验与必要模型对照；来源拿不到→适配/缓存；角色截断→数据关系；目录冗长→简介差异合并；重复建档→待研究候选与事务幂等；人工太多→系列共用证据和审核界面。先定位问题，再决定是否引入其他模型或扩大搜索。
