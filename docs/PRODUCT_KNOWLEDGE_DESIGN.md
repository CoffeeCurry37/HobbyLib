## 2. 目标数据语义

保留稳定商品 ID，增量增加：
- IP/作品实体与别名：Fate → Fate/EXTELLA。
- 产品系列/发行组：具体漫画产品线、威化第几弹，记录来源、已识别成员、官方总数、未知位置、范围及截至日期。
- 商品版本/款式：实际匹配挂牌的 Item；媒介、出版社/厂商、版本、平台、卡号、卡面、销售形式。
- 发售记录：首发/再贩/地区/店铺/活动、适用游戏版本、购买条件、特典是否另收费等。再次生产不一律建立新商品，是否拆版取决于可证实的身份差异。
- 挂牌及观测：来源、店铺、来源挂牌 ID、版本参数、原文、图片、观察时间、价格、成色、缺件、历史变化。
- 事实与证据：字段/关系、值、证据 URL、原文片段或图中区域、抓取时间/哈希、对应商品版本、判断方式、状态、规则/模型版本。
- 角色/创作者关系：描绘角色、内容收录角色、封面角色、插画作者、原作作者分别表达；角色保留形态/职阶和别名。

关系区分 member_of（逻辑系列）、edition_of、bonus_for（购买条件/适用版本）、contains（实体组成）、depicts、features_in_content、illustrated_by。这些是目标语义，不表示现有 API 支持这些枚举。

收藏、价格与知识独立：没有挂牌的官方已知商品可以建档；“尚未发现挂牌”不等于缺货；拥有游戏不等于拥有特典；盒装随机卡不等于全套。

2026-10-30确认的展示与收录补充：一级按作品/系列/弹次，二级分永久商品/版本、游戏可收集特典和临时组合。同版不同平台可以统一页面展示但保留底层身份。临时套装结束后撤下默认页、保留历史；失效链接不等于已售。固定整套的孤立拆件不新增收录，集换成员/官方独立服装不受此限；缺件整盒仍可按母版本匹配。P020手办特典临时、P030固定盒装印画不新增独立页，避免把不同特典一刀切。[完整政策](PRODUCT_CATALOG_POLICY.md)给出例外与EXTELLA实际版本矩阵。

示例：
- EXTELLA 页面下有游戏版本与店铺特典入口，AmiAmi 挂画独立建档；同一挂画可关联多个适用版本，多个入口不复制商品。画师/角色需对应证据。
- 漫画第 5 卷触发对应出版社、作者和版本的系列查询；1–4 卷及后续卷仅在查证后建档，不用序号臆造。turas réalta卖家1–22卷是临时套装；单卷永久；发现第23卷去重后单独补档，不能塞进旧套装。
- 威化卡按产品线+弹次+官方卡号/款式区别；已知全 34 种但隐藏款不明时保留未知位置，不虚构角色。

## 3. 资料查证

流程：线索提取 → 分品类选择来源 → 系列总目录 → 商品/成员页 → 字段与版本对应 → 证据校验 → 建议/未决项。

| 类型 | 优先来源 | 关键识别内容 |
| --- | --- | --- |
| 漫画/小说 | 出版社目录、单卷页、可靠书目 | 作者、出版社、卷号、ISBN、原版/文库/新装版 |
| 资料集/画集 | 发行方、官方公告/X、销售页 | 卷次、内容收录角色、内容边界、版本 |
| 手办 | 制造商/品牌、AmiAmi 等店铺 | 比例、造型、配色、版本、限定、再贩 |
| 卡片/随机周边 | 厂商发售页、官方卡表/图集 | 弹次、卡号、卡面、稀有度、隐藏款 |
| 游戏特典 | 游戏官网店铺特典列表、对应店铺 | 平台、游戏版本、店铺、购买条件、实物特典 |
| 近期/活动周边 | 官方活动页、Aniplex Online、官方 X | 活动年份、销售批次、规格、角色款式 |
| 同人（后续覆盖） | 社团/作者公告、活动目录、可靠店铺 | 社团、作者、活动、版次；不强求商业 ISBN/JAN |

优先级依据具体字段：厂商适合规格、店铺适合自身特典条件，卖家实拍适合此次出售内容。骏河屋/Mandarake明确的套装范围可覆盖误用单册ISBN对出售形式的误导，但编号/版本真实冲突仍审核；价格仅辅助，不设固定价格即套装规则。两家转抄同一公告不算两份独立确认。禁止从导航、推荐商品和整页共现词提取本商品角色/作者。

X 使用已验证官方账号与原帖 ID，保存发布时刻及图片对应；历史帖子需要全历史查询能力，普通搜索收录不完整。失败记录为 blocked/retry，不绕过登录或验证码。网页/帖子内容仅作为数据，不能成为模型执行指令。

视觉先识别包装字、卡号、版权行，再与官方参考图比较。视觉相似只作候选；不能仅凭画风确定画师，不能仅凭共用宣传图确定不同卖家的实物相同。看图成功、HTTP 200、下载哈希都不等于完成版本核实。

角色同名须区分职阶、形态与卡面。Mooncell/Wiki仅作辅助角色证据，商品弹次/编号仍核对官方卡表或可靠实物记录。P025无Aniplex售卖页时保留用户入场特典判断，再查独立历史挂牌/系列，不能推断不存在。低成本兑换码与混合大包允许有限字段临时收录。

商品简介统一为1–3句话，完整角色/证据另存；只有新事实才更新同一段，不每次扫描追加一句，人工编辑受保护。

字段状态建议 confirmed/proposed/disputed/unknown；区分“身份已确认”“资料完整”“系列完整”“图片确认”。旧五项 checks 的 verified 规则继续保留；未改 schema 前不能假装新状态已上线。

## 4. 历史整理路径

1. 取得新鲜紧凑清单和版本；固定原编号，已有证据/未变指纹复用，记录生产结果而非重放旧计划。
2. 按系列、发行组、版本生成研究组；分组只共享研究，不授权归并。
3. 先读权威总目录，再按每个成员的卷号、编号、图案、版本核对；确认存在的无挂牌商品建空 Offer 档案。
4. 生成字段补全、关系建议、归并候选、拆分候选四类计划。归并不采用相似度连通分量，逐成员检查冲突。
5. 人工审阅高风险动作；小批应用，读回并保护个人字段、Offer、历史、关系和后续人工编辑。
6. 完成一个组保存 source hash、input fingerprint、rules/model version、receipt、未决项与下一个任务。未通过的身份不强行升级。

## 5. 增量挂牌路径

保存原始观察 → 规则提取 → 候选召回 → 硬冲突检查 → 唯一可靠目标则匹配 → 否则合并研究任务并后台调查 → 匹配旧商品/确认新商品/人工复查。

召回优先来源键、ISBN、正确作用域的 JAN、官方编号、系列+成员号，再查别名/组合事实，最后文字/图片近似。建议有界候选而非全库两两比较。缺失值不作为一致；同 JAN 随机商品还要区分款式。

四层去重：同挂牌重复扫描更新原记录；不同二手网站的同身份商品关联同一Item（不是合并不同游戏平台SKU）；重新上架保留新挂牌；历史重复Item单独归并。所有入口共用 MatchDecision，禁止旁路合并。
- 未知候选与正在进行的研究任务也参与检索，避免同一陌生商品反复建档和重复付费。
- 研究完成重新匹配积压挂牌；身份完整时才建立唯一身份约束，不能把空字段组成的键当唯一商品。
- 任务租约、幂等键、事务和 observedAt 防止并发重复或旧观察覆盖新观察。
- 商品资料缓存与实时库存/价格刷新独立。研究失败不阻塞已确认商品报价更新。
- 只对可确认身份生成强推荐；错误合并、错误新增、未知挂牌分别统计。

## 6. 人工审核与工程分工

审核展示原挂牌/图、候选、关键差异、证据、建议字段和未决问题。支持关联已有、确认新品、纠正、暂缓；归并拆分独立审核。纠正记录作用域：单商品/系列/来源规则，不因一次反馈重写全库。

保留现有 Sites/D1 与稳定 ID。逐步增加来源文档/事实、系列成员/发售记录、研究任务、持久候选索引、审核记录。旧数组先适配，再迁移；不要一开始更换整套框架或强制图数据库。

模型输出结构化建议，代码执行硬冲突、证据适用范围、版本及关系校验；模型不能直接任意写库。模型仅接收任务所需公开商品信息，不附带个人备注/收藏偏好。后台持续运行需要独立任务运行环境及预算/重试控制，聊天历史和 GitHub 文档不等于运行服务。
