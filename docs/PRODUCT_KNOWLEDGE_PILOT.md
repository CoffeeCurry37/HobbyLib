## 1. 选择工具：Codex 主导实施，ChatGPT 辅助调查，运行期使用后台+模型 API

“GPT”是模型家族，ChatGPT/Codex 是工作环境，不是互斥模型阵营。本项目选择依据工具、权限、持久数据与评测，不以聊天入口名称推断准确率。

| 工作 | 建议承担方 | 交付 |
| --- | --- | --- |
| 需求、目录语义、少量难例调查 | ChatGPT 或具备搜索/看图能力的 Codex | 来源、字段决定、未决问题 |
| 现有32条修订读取/应用/读回 | Codex 连接当前项目与获授权的网站 | 真实回执、页面、差异、保护项 |
| 新数据结构、接口、脚本、测试和部署 | Codex | 可审查提交、迁移、回归、回滚 |
| 大规模持续识别 | HobbyLib 后台任务+可更换模型/搜索接口 | 幂等任务、事实、决定、成本日志 |
| 最终语义验收与困难裁决 | 用户/具备领域知识的审核者 | 标签、理由、适用范围 |

当前可继续使用 Codex 作为主工作台，无需为了查商品整体迁移工具。ChatGPT 深度研究适合某系列专题，但长报告不会自动变成可用商品库，必须转换成结构化证据并校验。Codex 也可进行研究，取决于实际接入的搜索/视觉/网站工具。

不宣称 Claude、Gemini 或其他厂商优于/劣于当前模型，本次没有横向实测。先预留模型适配接口；只有错误分析指向模型能力、或成本/延迟不足时，才对同一盲测集比较。日文小字可先补 OCR/清晰图片；网址失败先修来源获取；字段溢出先修数据模型，换模型不能解决这些问题。

如后续比较其他模型：使用同一原始证据、同一冻结测试集、同一预算和输出结构；比较身份正确、无依据字段率、拒答率、耗时、重试和每个正确结果的成本。先仅对困难子集试用，且另行确认外部数据处理范围。不要让多个模型互相同意充当真实标签。

依据（查阅于2026-10-29）：
- [Codex CLI](https://learn.chatgpt.com/docs/cli)：代码、命令、仓库和重复工作流。
- [官方提示指导](https://learn.chatgpt.com/docs/prompting)：Codex 用于代码/代码库/开发工具。
- [ChatGPT 搜索与研究](https://learn.chatgpt.com/docs/web-search)：多来源调查及可检查报告，依账户工具可用性。
- [Responses API](https://developers.openai.com/api/reference/responses/overview)：文本/图片输入、工具及结构化结果的应用接口。
以上支持工具能力；表中的具体分工是对 HobbyLib 的工程建议。

## 3. 阶段 B：300条真实记录的受控试点

当前已按用户明确授权完成300条准备与首30研究，旧语义问题保留而未重放生产修订。下列抽样数字是原目标，实际分层为书籍46、卡片60、游戏60、手办40、近期周边22、拼套/其他72；不足与困难程度见[首批报告](../research/pilot-300-20261029/REPORT.md)，不能把其他72全称为已标注困难样本。仍只在隔离数据/只读建议中做，验收前不扩大自动生产写入。

抽样单位为真实挂牌观察，另统计唯一商品数与系列数。建议互斥主分层总计300：
| 主分层 | 数量 | 检验点 |
| --- | ---: | --- |
| 漫画/小说/资料集 | 60 | 卷次、版型、同名产品线；至少15条资料集 |
| 卡片/随机周边 | 60 | 弹次、共JAN、卡号、同角色不同卡面 |
| 游戏及店铺特典 | 60 | 平台、版本、本体/特典、购买条件 |
| 手办 | 40 | 厂商、比例、造型、限定/再贩 |
| 近期官方周边 | 40 | 官方系列、活动年份、角色规格 |
| 拼套/信息残缺/矛盾挂牌 | 40 | 拒绝误判、部分成员、来源冲突 |

困难层可另加品类标签但不重复计数。组合上述分层后，尽量覆盖约120个已有商品匹配、60个真实库外新品、60个易混淆负例、60个应暂缓案例；不足的真实样本如实报告，不能用生成标题假装真实数据。至少覆盖3种来源，兼顾有图/无图、已知/未知系列，不能全部挑官方资料齐全的简单商品。

实际冻结按100条挂牌开发、200条挂牌作留出候选（不是100/200个独立组）；开发中首30已研究，后70未运行。冻结候选尚需组泄漏审计与独立参考答案，不能直接称已具备200条盲测。按商品及系列/发行组划分，同一商品多个挂牌、同一弹共用目录不能跨集合泄漏。实际组大小不整齐可调整数量并记录原因。旧32条属于开发/回归素材，不进入未见过的盲测；否则仅可报告“见过样本的回归”，不能报告泛化。

真实参考答案：
- AI先准备商品身份、版本、预期匹配目标、字段/关系、来源、未知项；人依据证据确认，记录审核者和时间。
- 不确定的正确答案可以就是“暂缓”，不能强行选择目标。高风险冲突二次复核；分歧保留裁决。
- 在锁定参考答案前，审核者尽量不看被测系统最终答案，降低确认偏差。
- 现有数据库里“没有搜到”不自动标成库外新品，需检查候选索引/别名/待研究记录。
- 冻结后不根据测试错误改答案迁就系统；来源事实纠错要版本化，改规则后重新用未见样本评测。

原建议按每30–50条自然组运行；实际首30已交付。下一步先按15点反馈做30条V2，交付验收后再分批处理70开发，规则冻结后才评测200候选。每批保存候选、查询、每个事实来源、判断理由、费用、耗时、人工修改及重放结果。

首次只需要四个可浏览展示：
1. 一套漫画/小说目录，卷次与版本正确，无挂牌成员也可见；
2. 一弹威化卡的成员和角色、已知/未知完整度；
3. EXTELLA 某店铺特典与游戏版本关系，画师/角色按证据确认；
4. 至少一册角色数超过15的资料集，完整角色关系可检索且不截断。
若某例缺原始证据则换同类有证据样本演示，并把原例保留为困难项；不得伪造用户例子已经查清。

## 4. 试点验收：质量、覆盖与成本同时衡量

以下为建议门槛，未实测；按品类/来源分别报分母、未知数与区间。

| 指标 | 建议门槛/处理 |
| --- | --- |
| 身份严重错配 | 已知卷号、平台、版本、本体/特典冲突的自动匹配为0；出现即停该路径并修复 |
| 无依据事实/错误确认 | 审核样本中不得把无依据推断标 confirmed；有URL但不支持字段仍算错误 |
| 证据可追溯 | 100%确认字段/关系可定位到支持它的证据；不可访问源用已保存的合规证据或保持未知 |
| 人工/收藏保护 | 测试及试点修订不改变保护字段，逐项验证；0丢失 |
| 重放/并发 | 同输入重放0重复Item/Offer/关系/事件；同任务并发不重复建档 |
| 候选召回 | 对已确认可匹配正例，正确目标进入候选的比例目标≥98%；候选预算同时报告 |
| 官方目录补全 | 对有完整官方清单的测试系列，成员/编号对应应全部正确；来源未公开者单列，不用来虚增覆盖 |
| 人工负担 | 普通案件审核中位数目标≤2分钟；困难案件单列，不压成确定答案 |
| 自动覆盖率 | 报全部挂牌和资料充分子集的比例；先测基线，不预承诺90%自动化 |
| 成本 | 报每条挂牌、研究组、正确商品、人工案件的实际费用；达预算上限暂停付费研究但保留输入 |

目标99.5%自动关联准确率是后续上线门槛，300条混合试点不能证明。单侧95%二项区间下，300次独立自动决定全对的下界约99.01%；600次独立自动决定全对约99.50%。若只自动决定部分样本，分母更小；同系列强相关需按组统计，不能机械套600。存在错误时需按实际区间和风险另评，不能只看点估计。

试点可以接受覆盖率不高但决定可靠；若成本/审核量不可接受则仍不扩量。用拒绝全部匹配取得零错误不算通过：同时报告候选召回、自动覆盖、可处理记录的未处理原因。

历史预算建议（不是已获付费授权）：先30条演练，按真实消耗预测后270条；原$50模型/搜索停止线仅为规划参考。当前尚未启用付费API，下一阶段以V2实际请求/缓存/人工时间重新估算并在启用付费服务前确定上限，不自动充值。未启用付费API前可用现有会话做人工辅助研究，但须把会话工作与API成本分列；$50不含订阅、人工、X或托管，也不是完成保证。

## 5. 按失败原因调整

| 失败表现 | 首选调整 | 验证 |
| --- | --- | --- |
| 正确商品没进候选 | 别名、分词、编号索引；必要时语义/视觉召回 | 分层正例召回，不只提升全局平均 |
| 候选有正确项却选错 | 品类充分证据、硬冲突、拒绝阈值 | 困难负例和未见系列 |
| 角色/画师张冠李戴 | 商品局部抽取、角色关系类型、署名证据、图像区域 | 字段级来源支持审阅 |
| 日文小字/卡号识别错 | 更清晰图片、裁切/OCR、读取背面；再评模型 | 同图同预算对照 |
| 资料集角色被截断 | 新增内容收录关系、分页与完整导入导出 | 超15角色样本及往返恢复 |
| 系列补全乱扩展 | 出版社/版本/活动作用域、官方成员表、未知槽位 | 同名不同系列负例 |
| 网站获取失败 | 来源适配、官方其他入口、缓存/退避、授权访问 | 获取成功率与真实正文率 |
| 新品重复建档 | 查询待处理候选、研究任务去重、事务/唯一约束 | 重放、乱序、并发 |
| 审核太多 | 共享系列证据、改审核页、只让人工处理分歧 | 审核分钟/组、重复问题数 |
| 费用太高 | 页面/字段缓存、缩小输入、便宜模型提取、难例升级 | 每个正确结果总成本 |
| 规则满是Fate特例 | 品类规则与IP词表分开、数据驱动目录 | 少量未见其他IP样本 |
| 扩量变慢 | 有界索引查询、增量写入、独立证据/观测表 | 定位历史3.10倍回退，再压测 |

只有“取到正确证据且流程/字段结构正确，但模型持续误读”的问题，才优先试更强或其他厂商模型。未来模型对照用新保留集，避免反复看同一盲测集挑冠军。

## 6. 阶段 C–E：实施最小版本、影子运行、受控上线

C. 最小代码范围（试点需要时实施，不先重写系统）：
- 来源/字段证据结构、内容角色关系、逻辑系列关系、研究任务状态；
- 持久化可查询的身份索引、资料建议与校验接口、审核差异页面；
- 模型/搜索适配层、每任务预算/缓存/错误回执；
- 复用当前MatchDecision/curation/事务保护；新增接口向旧备份兼容；
- 按实际改动运行相关既有回归及必要新验收案例，不重跑无关全库导入。

B与C可在隔离环境迭代：先人工辅助证据演练，再实现缺失的最小环节；不能把人工完成的300条结果冒充无人值守系统效果。代码冻结后在留出集重新测完整系统。

D. 影子运行建议至少7–14天且满足样本量，二者都满足才评估：
- 观察真实新增/变化挂牌，保存系统建议，暂不扩大自动生产归属；
- 若不能新采集，先用获授权历史观测回放验证工程，再明确缺少实时证据；
- 抽样必须包含自动匹配、拒绝、新品、困难来源；用户反馈和参考答案独立记录；
- 达到自动匹配目标与成本门槛后，只开放验证过的品类/来源。数量不足延长，不因时间到了宣布通过。

E. 分批上线：
- 先准确编号/已确认目录的已有商品匹配，再有限开放证据充分的新品；
- 历史归并、拆分和不明实物拼套继续审核；
- 第一批只处理有限样本并逐项读回，确认后扩大；异常可停相关来源/品类并撤销受影响决定；
- 每周看错配、重复建档、未决积压、审核量、成本和来源失败；规律变化触发重新校准。
跨IP扩展先做小规模独立验证，同人另设来源策略，不把Fate规则直接套用。
