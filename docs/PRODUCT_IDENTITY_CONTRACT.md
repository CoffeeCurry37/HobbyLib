# 商品身份、层级、标签与市场事件契约

2026-10-26。本文规定演进约束；“目标”字段与流程需实施和验证，不能被解读为当前 API 已支持。当前实体定义以 lib/radar/types.ts 为准。

## 实体映射

| 概念 | 当前载体 | 契约 |
| --- | --- | --- |
| 商品版本/款式 | Item，稳定 id | 身份独立于价格、成色、店铺标题与目录位置 |
| 系列档案 | Item.catalogueGroup、catalogueGroupType、catalogueKey | 逻辑分组，不冒充可售实物或完整成员清单 |
| 挂牌 Listing | Item.offers 中的 Offer | 来源、店铺、URL/来源键、变体、状态、观察及核验时间、价格与历史 |
| 浏览目录 | CatalogNode、catalogNodeId 与 taxonomy 推断 | 可以调整路径，不改变商品身份 |
| 组成/相关关系 | Relation：contains、bonus、related | 方向、数量与证据明确，contains 无自环、悬空或环路 |
| 个人收藏 | Item 的 ownership、quantity、notes 等 | 当前与商品同存；未来拆分必须无损迁移 |
| 核实证据 | Evidence 与 EditorialReview | 来源事实和人工判断分开；事实改变使相关核实过期 |

示例：某小说系列档案 → 第 1 卷原版、第 1 卷文库版；漫画改编属于另一产品线。第 1 卷原版可关联某店铺购入特典；卖家“1–10 卷套装”是独立卖家拼套，与十卷组成关系相连，不能合并到小说系列档案。

## 身份与 Listing 键

- 身份事实包含作品、媒介、产品线、卷号/成员号、出版社/厂商、版本、平台、发行活动、赏别、卡号/卡面及销售形式；缺失值不是一致证据。
- ISBN/JAN 保留原值与来源。识别标准化格式及校验位；同 JAN 的一番赏、随机商品或共码款式必须进一步区分。ISBN 存入 JAN 的历史情况应兼容，有冲突则隔离，不能只看数字相同。
- 日文原名和来源刊载标题保留；别名用于召回，不作为推翻卷号或版本差异的理由。翻译和标点标准化不删除身份信息。
- 成色、带腰封、附属品缺失、报价及卖家状态原则上属于 Offer；独立发行特典、组件及不同限定包装须用明确规则判定。不能用“特典付き”把本体与特典单品合并。
- Listing 键必须是来源命名空间 + 有效商品/挂牌标识 + 店铺/变体等来源必要范围。缺少 itemCode 等关键参数时不得生成所有记录共用的键；追踪参数可去掉，真实变体参数不得去掉。
- 同挂牌键仅说明观测对象可能延续。来源复用 URL、变体变化、解析错误或旧关联冲突时，保留新观测并转复查，不得绕过身份检查覆盖原商品。

## 统一匹配决定（目标）

建议引入内部 MatchDecision，不直接改变现有公共 API，迁移时提供兼容适配：

```text
decisionId, inputFingerprint, rulesVersion, sourceKey,
status: matched | ambiguous | unmatched | conflict,
targetItemId?, candidateIds[], evidence[], conflicts[],
reasonCodes[], confidenceTier, observedAt
```

confidenceTier 是规则证据等级，不是模型自报概率。数值阈值必须通过留出集校准。算法顺序：

1. 有界索引召回；原始候选保留，避免仅第一命中。
2. 逐候选检查已知卷号、媒介、平台、版本、款式/卡面、独立特典、原厂套装与拼套等冲突。同 Listing 路径也必须执行。
3. 优先使用可信且适用范围正确的发行标识和权威目录证据，再用完整名称与组合事实；标题相似度、图像相似度、标签交集只能召回或提出建议。
4. 单一可靠且无冲突目标才可 matched；多目标无法消歧为 ambiguous；无候选为 unmatched；已有键映射但事实矛盾为 conflict。不能把这三者都当作新增已核实商品。
5. 保留观测并记录决定；未确认项进入待复查或 provisional 流程，不触发强购买建议。是否创建占位商品由兼容策略决定，不丢观测也不伪造正式档案。

历史两个 Item 的归并是另一个显式操作，需新鲜快照、成员指纹、个人字段冲突检查、关系完整性和可撤销存档。匹配算法不得直接调用批量归并端点。

## 层级、成员及拥有语义

同系列、多版本、同活动、特典关联与物理包含不可混为一种父子关系。逻辑档案按现有 family 规则适配；只有确认物理内容才生成 contains。父级、子级迁移前检查原目录、旧关系及预期成员数，保留未知成员与证据状态。

卖家拼套是此次 Listing 的出售范围；不按原厂全系列目录补齐缺失实物。只看到一张合照不能证明件数或齐套。每个组件、特典拥有状态独立；unknown 不等于 missing，不因拥有本体或父级就自动把子级设为 owned。跨套装重复数量不得重复计入收藏总数。

## 标签与事实

复用 characters、publisher、manufacturer、circle、artists、series、productLine、wave、kind、saleForm 等结构化字段；tags 用作检索和偏好维度，不承担唯一身份。

目标是命名空间化的受控词表：作品、角色、媒介、商品类型、厂商、活动、发行属性；保存规范值、别名、规则版本和字段证据映射。先提供兼容现有 string[] 的投影，不立即把全部旧标签强制替换。过时自动标签可以有审计地重算，人工标签与人工字段需明确保护；当前若无法判断来源，应保留并报告。

证据优先考虑出版社/厂商发行目录及商品局部结构化信息，再采用可靠店铺详情。搜索词、导航、推荐列表、模型背景知识不能充当商品事实。来源矛盾记录具体字段与双方证据，不静默选一方。图片必须对应实际版本；参考图、赏级图、目录图和卖家实拍沿用 imageRole 区分。

保留现有同人分级默认策略：classification.ts 在无显式成人提示时设 all；这属于历史用户策略，不代表已获得“明确全年龄”来源证据。不得在本轮擅自改变该策略，也不得把默认值作为版本一致或事实核实的充分证据。

## 增量、幂等与变更安全

来源观测、身份决定、商品修订、通知事件分别有可追溯键。相同输入重放不新增重复 Offer、Item、关系或通知；旧 observedAt 不覆盖新观测。持久保存游标、失败原因、缓存版本及规则版本，来源要求登录/验证码/年龄验证时暂停，不绕过。

写入前重新读取目标并核验 expectedVersion/指纹；规则变化使旧计划失效。数据库事务保护应覆盖相关 Item 及受影响关系，拒绝中途并发修改。归并撤销不能覆盖归并后用户编辑。所有脚本默认 dry-run，写入模式必须显式指定环境及范围；生产应用须另行授权。

## 通知与价格推荐

当前可用 Offer 条件：available、有 verifiedAt、核验距今在 [0,24h)、price 非 null、priceKind 非 closed。未来来源可用更短有效期，但缓存商品资料不能当实时库存。

当前 ingest 通知键由商品 id、Offer id、价格、库存状态和 stockEpoch 组成；补货 sold→available 增加 epoch。目标新增持久事件台账和明确的 new_listing/restock/price_drop 等语义，避免历史提醒裁剪后重放、跨路径或并发重复。记录规则版本、匹配结果、触发报价、推荐理由和生成时间；外部发送应采用事务 outbox 与幂等发送，但不在未配置渠道时虚构已送达。

价格建议只能比较已确认的相同商品版本；同版但成色或附件不同须分组/提示差异。竞拍当前价不当一口价；整套总价不当单件价；挂价不是成交价，历史高价不是市场公允价。当前降价加分只针对同一挂牌、同 priceBasis 的历史高价，不可宣传为跨市场估值。

目标到手价：商品价 + 日本国内运费 + 代购/服务费 + 国际运费 + 适用税费，以带时间的汇率转换。未知费用保留未知或区间，缺少价格/成色/附件/税费口径时不输出确定的“全网最低”。没有已实现的费用模型时展示 JPY 标价比较及缺项即可。

推荐分数仅排序，解释偏好、已拥有扣分、缺件收益、重复件比例及价格依据；身份可靠度与兴趣分数分离。禁止自动下单。
