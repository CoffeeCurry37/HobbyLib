## 正式规范

1. 作品、厂商、系列、活动先规范化再生成路径；同层、祖先和相关分支复用规范身份。大作品与 FGO 平行；书籍/卡片/周边从“综合”提到作品下。大型周边属于周边。Fate 玩具集中按类型（可动/静态/GK）、厂商、真实产品线、单品组织。其他 IP 玩具保持自己的作品。
2. 目录页只展示同层模块，商品仅在叶级；官方套装、随机盒、单品、临时卖家组合必须保留范围差异。临时组合回到所属系列；结束后退出当前展示但保留历史。永久商品零挂牌也保留。
3. 漫画、杂志、设定集、带卷号/裸数字的书籍和音像、一番赏、卡片、近期游戏、命名周边系列、活动商品触发系列查证；同人本轮不展开，GK 仅检图。按系列共享研究，避免每条重复联网。
4. 官方新增与扫描挂牌走同一身份入口。标题、商品号、媒介/版次/卷号、角色/卡号、图片、套装范围互相校验。店铺强标题可高于错配 ISBN，价格只作辅助。图文冲突进入待明确，不强行归并。图片取得与规则匹配不等于已核实。
5. 商品标题和简介描述商品本身，挂牌原文、价格、状态另存。简介 1–3 句，不随每次扫描追加。证据来源/时间与图片来源保留；已认可、已失效旧资料不重复查证。
6. 合并只处理同一商品身份；卷号、不同媒介、版次、卡面、单品/套装、特典/本体不能混合。同版不同平台仅聚合展示。关联改动与用户字段、Offer 历史、原编号必须完整保留；不把全库批量标成 verified。

## 执行与恢复

先获取实时完整备份，保存未改原件和指纹；使用正式源码副本实施并在备份副本上生成具体变更/合并计划。分批写入，每批写前读取目标，用版本及关系保护，写后复读验证；保存实际成功回执后才进入下一批。失败/冲突停在该批重新规划，不重复成功操作。GitHub 保存规则、代码及脱敏断点，完整备份和凭证不上传。正式站原项目、DB、访问权限不变。

当前状态：2026-11-03 正式整理已完成，Sites 70 已部署。477 批 9,531 条变更和 25 组精确合并均已复读验证，当前 35,000 有效、8,574 存档、1,824 关联。维护入口已关闭，具体见正式报告及 rollout.json。V5 的 300 条研究不等于全库核实；1,848 个系列研究分组仍需证据。

演练发现：已有 editorial 的记录不能补写卷号或其他依据字段，否则会使已认可的复核依据过期。V6 自动规范化和官方补全均保留此类记录原文，仅通过目录路径统一展示；不伪造新的复核依据。整理接口保留已存详情图片，不再无声截断到十张。

恢复入口：`scripts/plan-v6.mjs` → `scripts/validate-v6-plan.mjs` → `scripts/apply-v6-batches.mjs`。真实写入须有成功演练报告；每批最多 20 条，拆分媒介的两个目标在同批内原子提交；写前版本校验、写后完整复读，回执即时落盘。运行文件和备份位于正式源码副本的 `work/v6/`，不提交凭据或完整个人数据库。

合并规则修正后：保留目标已认可的完整事实、图片及复核依据，25 组精确身份候选全部通过实际 API 副本检查并正式合并。禁止用推断标签覆盖已认可字段。相同关系的重复边只有数量一致时才能归并；不同历史挂牌观测可聚合为当前状态，但原始两条商品、全部 Offer 与关系必须完整保存在可撤销归并档案，不能把聚合视为一次新的库存核验。

旧目录兜底不能默认认为一番赏属于 Fate；已知其他作品保留自身作品，未知作品进入待归档。旧 Fate 模块映射至 Fate 综合，原个人目录字段保留，避免跨分支再造重复入口。

同名保护也适用于角色名：菲特·泰斯特罗莎属于《魔法少女リリカルなのは》，不是 TYPE-MOON Fate。官方例证 https://www.goodsmile.info/ja/product/3671 。规范作品身份在匹配和路径生成前生效；已有原始标题/审核依据保留，目录可按明确的作品信号纠正。

正式数据整理全部完成后，成功回执是唯一恢复依据；当前不再有待重放批次。新请求应建立独立差异计划，不能重跑原始 plan-v6/validate-v6-plan 覆盖已冻结动作。原脚本是审计及下一次受控迁移的参考，不是周期任务。
