# Collector Radar v0.14.0 独立运行说明

v0.14.0：新增游戏版本、书籍系列、威化弹次和卡片款式目录；随机包与全盒同目录展示，官方编号与二手名称只按核实证据匹配。自动整理采用小批量版本校验。商品打开独立完整页面，图片最多 10 张；右侧展示资料与个人记录，按“编辑资料”修改，下方查看挂牌和关联商品。游戏本体、店铺特典、限定盒组件与卡片目录分别记录。

商品数据库与提醒助手；不自动下单。可以脱离 ChatGPT 网页运行。需要 Node.js 24+，不再使用 Python，也不需要输入“3.12”。

沿用的整理规则：同一次活动归到共同目录；BD/DVD 标为捆绑发售，游戏限定盒、全款周边套装和随机多款分别整理。Fate/FGO 手办统一在 Fate 综合 → 玩具，卡片等周边按类型归档。标题高频关键词成为可搜索标签，卡片显示短标题，原始标题和挂牌资料保留。搜索支持空格组合、#标签和 tag:关键词。

v0.12.0：每件商品保存一个主类别及对应标签：书籍、游戏、影像、周边、大型周边、卡片、玩具、同人。目录和筛选沿用这八类，一番赏及独立特典保留专门入口。原站“游戏相关”“游戏原作系”等大类不再把漫画、OST 或周边变成游戏；系列以商品标题和局部信息判断，避免搜索词或关联作品污染。不同游戏平台、卷号、原版与新装版保持独立。

一番赏按期次、赏级、款式建立 5 期、44 个赏级档案。奖品的一包多件仍视为一款。单款图、全赏套图、赏级参考图分开提示，未知款式显示空位。详情支持多图；来源图片加载失败时尝试受限的图片转接，再显示“图片待补”。两个 Yahoo 拼套已逐件核对实拍并保留原图指纹，其中新的四盒手办组合跨两个活动。其他组合仍需检查，没有接入通用 AI 图片识别服务。

Aniplex 本轮补采京まふ、AnimeJapan、TYPE-MOON Comiket 及当前目录；AmiAmi 继续历史与二手入口。出版社逐 ISBN 核对 624 个实体版本（另有 84 个电子专售记录已排除），另补讲谈社《turas realta》23 卷发行档案。未来发售日照实保留，不当作现在有货；失效和未公开的封面继续留空。实际数量、采集失败和下一页见 release-info.json 与 VERIFICATION.md。

明确刊载卷号范围的套装会优先匹配已有单卷，缺少的成员建立待核实记录，不推定价格或拥有状态。显示部分拥有和缺件；复核报价后比较补缺单买与整套售价，标出重复购买。已核实完结版本和原始捆绑套装常驻；其他卖家拼套仅有货时显示在成员下。需要的成员出现在详情确认有货的拼套中也可提醒。售罄无价格商品继续收录。

本包包含更新后的现有商品库及合并存档，3 卷已拥有小说保留。当前数量见 release-info.json。v0.12.0 增加 4,212 条来源观察，包含既有款式图片复核、在售商品和二手来源续采；统计包含重复挂牌。仍有二手网站分页、未标年份商品和受年龄确认限制的入口待补充。

## 第一次启动和升级

1. 先打开 `WINDOWS-QUICKSTART.html`。从 https://nodejs.org/en/download 安装 Node.js 24 LTS 的 Windows Installer（`.msi`）；保留默认的 PATH 选项。安装后关闭旧启动窗口。
2. 完整解压 ZIP，不要在压缩包内双击启动。
3. 浏览和整理商品只需双击 `START-WINDOWS.cmd`；暂时不用 START-BROWSER。打开 `http://localhost:8080`。
4. 从解压目录的 `data/studio-password.txt` 复制自动生成的工作室密码登录。不要把密码发到聊天里。
5. 本次完整数据包已内置你的数据库，直接启动即可；本地使用和服务器上线步骤见 `DEPLOY-AND-CONTINUE.zh-CN.md`。

本包是整理后的完整数据快照：请先解压到新文件夹，直接启动检查，不要用旧版 data 覆盖包内 data。如果旧本地版有尚未同步的新增收藏或备注，先在旧版导出备份，保留旧 data 目录；在线版和本地版不会自动合并这些变更。

只升级程序、继续使用旧本地数据时：停止旧程序，备份旧 data，再把旧 data 复制到另一个新版目录。此方式保留旧数据库，不会自动应用本包的整理结果。可在“重复检查与合并存档”中主动执行严格合并。原始条目留在合并存档；拥有状态或评分冲突交给人工核对。已修改过的归并条目不能直接撤销覆盖，请使用备份核对。

整库 JSON 迁移只允许目标库为空，后台监控默认关闭。文件上限 256 MB；页面会分块上传，检查全部条目和关联后再一次提交。中途失败不留下半个商品库，重新选择文件即可重试。HTML 和商品数组导入仍为 4 MB。在线版和独立版不会自动双向同步。

商品库默认按板块进入：作品 → 系列 → 产品类型 → 产品线 / 弹次 → 套装与单件。可新建、改名、移动板块，批量归档，并切换图标、详细列表和卡片；商品列表每页 60 件。已取消 2,000 条读取限制，并用 10,000 条模拟商品验证了迁移与备份恢复；实测范围见 `VERIFICATION.md`。普通目录分批读取，同人和合并存档按需读取；偏好、提醒、账号与侧栏助手在设置里按需开启。

## 推荐测试流程

1. 在采集工作台选择 Mandarake 的 TYPE-MOON 书籍搜索，采集列表。
2. 点击“逐条复核库存、店铺与资料”。每个商品下有多个挂牌，分别显示店铺、成色、含税口径、特典情况和价格历史。动态网页需下面的浏览器组件或页面采集。
3. 查看“重复检查与合并存档”。稳定挂牌编号和足够完整、无卷号/版本冲突的名称用于归并；相似名称仅推荐核对。不同卷、本体/特典、套装不自动混并。
4. 标记已有本体“已拥有”，把缺失特典或组件标记“未购买”。关联不会传播拥有状态。套装评分考虑缺失和重复组件。
5. 给商品打分或调整标签权重、白名单；愿望清单可直接加入商品通知白名单。所有提醒仍受黑名单和评分条件约束。

“小垃圾”仅指低价且明确是徽章、丝带、挂件等 goods；廉价书籍和不明物品保留正常收藏。未知价格不能被当成便宜。

库存至少要有详情页明确证据。售罄记录和未知库存不会提醒，超过 24 小时未复核的在售状态退出近期确认范围。Mandarake“在庫確認します”搭配购买按钮表示可申请购买，店铺仍需最终确认库存；界面和提醒保留这项说明。Yahoo 拍卖的当前出价与一口价分别显示。

手动导入 HTML/页面采集文件不触发购买提醒，需在线复核。历史价格从开始观察后积累，属于挂牌观察，不是成交价或完整历史；参考定价与挂牌价分开，运费另计。

## 动态网页与原站验证

普通启动不用安装项目依赖。想让独立程序渲染动态页面：

1. 双击 `SETUP-BROWSER.cmd`，安装可选 Playwright 和 Chromium（需要联网和额外磁盘空间）。
2. 安装成功后，关闭旧程序，双击 `START-BROWSER-WINDOWS.cmd`。
3. 后台浏览器用独立匿名配置读取公开网页，不使用账号购买页会话。需要年龄、登录或人机验证时暂停，不自动点击验证。

也可以使用包内 `browser-extension`：Chrome / Edge 扩展管理页开启开发者模式，加载该目录。正常打开原站并完成需要的操作后，点扩展选择“公开商品”，导出已加载页面 JSON，再在雷达采集工作台导入。扩展只在点击时读取当前页；分页需逐页采集。

遇到动态内容缺失时只暂停详情任务，搜索任务仍可执行；年龄/登录/人机验证暂停该来源的自动读取。完成验证并不等于服务器取得了同一会话。原站浏览器可用于手动采集；独立程序的在线复核成功后才解除对应暂停，搜索任务还需在监控状态中恢复。

本机浏览器组件和扩展已实现，但本次没有执行真实 Windows 安装或完整扩展交互验收；若网站更改结构，应以提取预览为准。

## 账号购买记录和愿望清单

不在雷达或聊天里输入商店密码。在“账号记录”选择平台，独立版可打开本机专用浏览器，让你在原站登录；登录会话留在本机 `data/browser-profiles`。之后自己打开购买记录或愿望清单，点击读取当前列表。

在线版可使用扩展的“购买记录”/“愿望清单”模式，下载 JSON 后上传到“账号记录”。两种方式都只读取当前已加载页。

先预览标题、数量、状态、库内匹配；取消无关推荐商品，改正不确定匹配。购买记录必须确认已完成才标记拥有，取消/退款/待支付记录排除；愿望记录加入商品白名单。页面缺少商品链接或结构不符时，用页面里的 JSON 模板补录。没有可靠订单行编号时数量取较大值，不累计，重复导入不翻倍；多次买入同商品请手动调整总数量。

只标记确认的具体商品，不推断随附特典、其他卷或套装组件也已拥有。本次没有连接你的真实账号，四个平台的真实订单页尚未完成端到端验证。

## 自动整理、推理和翻译

采集时自动提取明确的出版社、厂家、角色、社团、画师、发售时间、JAN/ISBN、参考定价和关键词，形成标签，保留出处。少量已核对目录资料随版本提供；详情“自动搜索补全”优先 ISBN，否则只接受名称/卷号/版本严格一致的目录结果。多候选、缺失字段和受限页面保持待核对。小垃圾跳过深入搜索。

当前没有接入 ChatGPT/OpenAI API 或本地大模型。分类和关联使用规则，偏好学习使用你给出的评分，翻译使用可编辑术语词典、保留日文原名。没有全网自主推理或 AI 翻译，也不会产生模型 API 费用。

## 24 小时运行

在独立版采集工作台设置监控网址与 15–1440 分钟间隔并保存。程序关闭网页后仍运行；程序和电脑/服务器本身必须保持运行。任务逐页执行、保存分页进度，普通失败退避，验证要求暂停；空闲时逐条复核商品详情。站内收件箱会积累符合条件的新挂牌/变价提醒。邮件、Telegram 和手机推送尚未接入。

常开服务器可使用包内 Docker Compose（默认不带浏览器）或 Node.js 24。未代购服务器或创建付费服务，未部署独立生产主机。

Docker：在包根目录建立 `.env`：

```dotenv
RADAR_PASSWORD=replace-with-your-own-long-password
RADAR_ORIGIN=http://localhost:8080
```

密码至少 16 字符。运行 `docker compose up -d --build`。默认端口只绑定 `127.0.0.1:8080`；公网请通过 HTTPS 反向代理并将 `RADAR_ORIGIN` 改成准确域名。数据保存在 `radar-data` 卷，不要删除该卷。

无 Docker：设置 `RADAR_PASSWORD`、`RADAR_ORIGIN`、`RADAR_DATA_DIR` 后运行 `node dist-standalone/server/server.mjs`，用系统服务管理器保持进程。Linux 的可选浏览器需要系统依赖；可在包根执行 `node setup-browser.mjs`，再按 Playwright 的系统依赖提示安装。可见账号浏览器需要桌面环境，不适用于默认无界面的 Docker 配置。

定期导出 JSON。复制 SQLite 文件前停止应用或使用 SQLite 备份，保留整个数据目录，避免遗漏 WAL 和会话密钥。数据库、登录会话和工作室密码都属于个人数据。

实际执行的验证和未测试环境见包内 `VERIFICATION.md`。没有完成真实 24 小时持续运行验收。
